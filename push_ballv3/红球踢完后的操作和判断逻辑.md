# 红球踢完后的操作和判断逻辑

## 一、红球踢完的判断标准

### 核心判断代码

在 `main/ball_push.c` 的第 **239-243行**：

```c
case BALL_PUSH_PUSH:
    /* HARD PUSH: fixed strong straight command. No visual steering can
     * kick the ball sideways once geometry has been confirmed. */
    c->stage_ms=sat_add(c->stage_ms,ms);
    out.forward=PUSH_HARD_FORWARD; out.active=true; out.drive_mode=BALL_DRIVE_OPEN;
    if (c->stage_ms>=PUSH_HARD_PUSH_MS) {
        if (c->attempt==0) c->red_pocketed=true; else c->blue_pocketed=true;
        if (c->attempt+1>=2) { c->state=BALL_PUSH_DONE; return zr(c,true); }
        ++c->attempt; c->retry=0; reset_stage(c,BALL_PUSH_EGRESS,PUSH_EGRESS_REVERSE_COUNTS,l,r); out.state_changed=true;
    }
    break;
```

### 判断逻辑详解

| 条件 | 说明 |
|------|------|
| `c->state == BALL_PUSH_PUSH` | 当前状态为硬推状态 |
| `c->stage_ms >= PUSH_HARD_PUSH_MS` | 推球持续时间达到配置的时间 |
| `c->attempt == 0` | 当前是第一次尝试（红球） |
| `c->red_pocketed = true` | **设置红球已入袋标志** |

### 关键配置参数（board_config.h）

```c
#define PUSH_HARD_FORWARD              140   // 硬推速度
#define PUSH_HARD_FORWARD              300   // 最终强力冲击速度
#define PUSH_HARD_PUSH_MS              650   // 硬推持续时间（毫秒）
#define PUSH_HARD_PUSH_COUNTS          1400  // 文档参考值（实际使用的是时间控制）
```

### 判断标准总结

**红球踢完的标准是：**
1. ✅ 进入 `BALL_PUSH_PUSH` 状态（硬推状态）
2. ✅ 持续推球时间 ≥ 650毫秒
3. ✅ 自动设置 `red_pocketed = true` 标志

**注意：**
- 不依赖视觉判断（不检查球是否真的进入球洞）
- 纯粹基于时间控制（推650毫秒就认为成功）
- 原因：球洞可能是黑色开口，球进入后立即消失

## 二、红球踢完后的操作流程

### 状态机流转图

```
红球推球完成判断
       ↓
[BALL_PUSH_PUSH] 状态持续650ms
       ↓
设置 red_pocketed = true
       ↓
检查是否还有球要推
       ├─ 是（attempt=0）→ [BALL_PUSH_EGRESS] 开始寻找蓝球
       └─ 否（attempt=1）→ [BALL_PUSH_DONE] 任务完成
```

### 详细操作步骤

#### 步骤1：设置红球已入袋标志
```c
if (c->attempt==0) c->red_pocketed=true;
```
- 将 `c->red_pocketed` 设置为 `true`
- 这个标志会通过 `publish()` 函数发布到状态接口
- 可以通过 `ball_push_get_status()` 获取

#### 步骤2：检查是否完成所有球
```c
if (c->attempt+1>=2) {
    c->state=BALL_PUSH_DONE;
    return zr(c,true);
}
```
- `attempt=0` 表示红球（第一次尝试）
- `attempt=1` 表示蓝球（第二次尝试）
- 如果 `attempt+1 >= 2`，说明红球和蓝球都已完成
- 进入 `BALL_PUSH_DONE` 状态，任务结束

#### 步骤3：开始寻找蓝球（如果还有球要推）
```c
++c->attempt;  // 从0增加到1，开始寻找蓝球
c->retry=0;   // 重置重试次数
reset_stage(c,BALL_PUSH_EGRESS,PUSH_EGRESS_REVERSE_COUNTS,l,r);
out.state_changed=true;
```
- `attempt` 从 0 增加到 1
- 重置重试次数为 0
- 进入 `BALL_PUSH_EGRESS` 状态
- 设置倒退目标：`PUSH_EGRESS_REVERSE_COUNTS` 个编码器计数

## 三、EGRESS 状态详解

### EGRESS 配置参数（board_config.h）

```c
#define PUSH_EGRESS_SPEED              120   // 倒退速度
#define PUSH_EGRESS_REVERSE_COUNTS     650   // 倒退目标距离（编码器计数）
```

### EGRESS 状态代码（ball_push.c 第246-251行）

```c
case BALL_PUSH_EGRESS: {
    bool stalled=tick_counts(c,ms,l,r);
    if (stalled) { c->state=BALL_PUSH_FAULT_STOP; return zr(c,true); }
    out.forward=-PUSH_EGRESS_SPEED; out.active=true; out.drive_mode=BALL_DRIVE_APPROACH;
    if (c->stage_progress>=c->stage_target) { reset_stage(c,BALL_PUSH_FIND_BALL,-1,l,r); out.state_changed=true; }
    break; }
```

### EGRESS 状态的功能

| 操作 | 说明 |
|------|------|
| 倒退 | 以120的速度向后退 |
| 距离控制 | 后退650个编码器计数 |
| 防止卡住 | 检测是否卡住（`stalled`检测） |
| 自动切换 | 完成后自动进入 `FIND_BALL` 状态 |

### 为什么要EGRESS？

1. **离开球洞区域**
   - 避免球洞边缘干扰视觉
   - 防止意外再次碰到红球

2. **为寻找蓝球创造空间**
   - 清理视野
   - 重新定位

3. **防止状态机混乱**
   - 确保从红球场景完全退出
   - 为蓝球任务创建干净的环境

## 四、蓝球任务开始

### 从 EGRESS 到 FIND_BALL

```c
if (c->stage_progress>=c->stage_target) {

```

### FIND_BALL 状态（ball_push.c 第115-118行）

```c
case BALL_PUSH_FIND_BALL:
    if (ball) { reset_stage(c,BALL_PUSH_APPROACH_BALL,-1,l,r); out.state_changed=true; break; }
    reset_stage(c,BALL_PUSH_SCAN,PUSH_SCAN_FIRST_COUNTS,l,r); out.state_changed=true;
    break;
```

### 蓝球任务配置（board_config.h）

```c
// 任务映射
```

### 蓝球识别和推进

蓝球任务的流程与红球相同，但：
1. 目标颜色是蓝球（`BALL_COLOR_BLUE`）
2. 目标球洞是右球洞（`side=1`）
3. 使用蓝球识别参数（可能需要调整）

## 五、完整状态机流程

### 红球任务（attempt=0）

```
START_FORWARD (起始直行)
    ↓ 650ms
FIND_BALL (寻找红球)
    ↓ 发现红球
APPROACH_BALL (接近红球)
    ├── 阶段0：侧移对齐
    ├── 阶段1：远距离转向球洞
    └── 阶段2：直行接近
    ↓ 球足够近
ALIGN (对齐)
    ├── 侧移对齐球洞
    ├── 旋转对齐球洞
    └── 确认保持300ms
    ↓ 对齐完成
PUSH (硬推)
    ↓ 650ms
    └─ 设置 red_pocketed = true
    └─ attempt 从 0 增加到 1
    └─ 进入 EGRESS
```

### 蓝球任务（attempt=1）

```
EGRESS (倒退离开红球洞)
    ↓ 后退650计数
FIND_BALL (寻找蓝球)
    ├─ 发现蓝球 → APPROACH
    └─ 未发现 → SCAN 扫描
APPROACH_BALL (接近蓝球)
    ↓ 球足够近
ALIGN (对齐)
    ↓ 对齐完成
PUSH (硬推)
    ↓ 650ms
    └─ 设置 blue_pocketed = true
    └─ attempt 从 1 增加到 2
    └─ 检查：attempt+1 >= 2
    └─ 进入 DONE
```

### 任务完成

```
BALL_PUSH_DONE
    ↓
    ├─ done_logged = true (只记录一次)
    ├─ locked = true (停止移动)
    └─ 日志输出："pocket-push task COMPLETE: both balls pocketed"
```

## 八、错误处理和重试

### 重试机制（board_config.h）

```c
#define BALL_TASK_RETRY_MAX              3   // 每个球最多重试3次
#define BALL_TASK_TIMEOUT_MS         180000   // 整个任务超时（3分钟）
```

### 如果推球失败

如果 `PUSH` 状态后没有成功进入 `DONE`，可能：
1. 超时：整个任务超过180秒 → `BALL_PUSH_FAULT_STOP`
2. 卡住：轮子不转 → `BALL_PUSH_FAULT_STOP`
3. 重试次数过多：单球重试超过3次 → `BALL_PUSH_FAULT_STOP`

### 故障状态（ball_push.c 第91行）

```c
if (c->task_ms>=BALL_TASK_TIMEOUT_MS) {
    c->state=BALL_PUSH_FAULT_STOP;
    publish(c,false,false);
    return zr(c,true);
}
```

## 十、常见问题

### Q1: 如何判断红球已经踢完？
**A:** 观察 `red_pocketed` 标志是否为 `true`，或者状态是否从 `HARD_PUSH` 切换到 `EGRESS`。

### Q2: 如果红球没有真的进洞怎么办？
**A:** 系统不会视觉验证球是否进洞，纯粹基于时间控制。如果球没进洞但650ms已过，系统会认为成功并开始找蓝球。

### Q3: 可以修改判断标准吗？
**A:** 可以修改 `PUSH_HARD_PUSH_MS` 的值。如果需要视觉验证，需要修改 `BALL_PUSH_PUSH` 状态的逻辑。

### Q4: EGRESS 倒退距离可以调整吗？
**A:** 可以修改 `PUSH_EGRESS_REVERSE_COUNTS` 的值。当前是650个编码器计数。

### Q5: 如何跳过红球直接推蓝球？
**A:** 修改 `main/camera_vision.c` 第185-189行，让蓝球识别优先级更高，或者修改推球控制器直接从蓝球开始。

### Q6: 红球和蓝球的顺序可以调换吗？
**A:** 可以修改 `board_config.h` 中的 `BALL_TASK_FIRST_COLOR` 和 `BALL_TASK_SECOND_COLOR`。

## 十二、总结

### 红球踢完的判断
- **标准**：推球持续650ms
- **标志**：`red_pocketed = true`
- **方式**：纯时间控制，无视觉验证

### 红球踢完后的操作
1. 设置 `red_pocketed = true`
2. 检查是否还有球要推
3. 如果有蓝球要推：
   - `attempt` 从 0 增加到 1
   - 进入 `EGRESS` 状态
   - 倒退650个编码器计数
   - 进入 `FIND_BALL` 状态开始找蓝球
4. 如果没有球要推：
   - 进入 `BALL_PUSH_DONE` 状态
   - 任务完成，停止移动

### 关键时间参数
- `PUSH_HARD_PUSH_MS` = 650ms（推球时间）
- `PUSH_EGRESS_REVERSE_COUNTS` = 650 计数（倒退距离）
- `BALL_TASK_TIMEOUT_MS` = 180000ms（总超时时间）
