# 蓝球识别问题诊断和解决方案

## 问题分析

### 当前配置（board_config.h）

```c
// 蓝球像素分类阈值
#define BALL_BLUE_MIN_BR_DOM            25   /* B - R 色度优势 */
#define BALL_BLUE_MIN_BG_DOM            25   /* B - G 色度优势 */
#define BALL_BLUE_MIN_B                 50   /* 蓝色通道绝对下限 */
#define BALL_BLUE_MIN_SAT               45   /* 饱和度下限 */
#define BALL_BLUE_GRADIENT_MIN           3   /* 球体明暗梯度最小值 */
#define BALL_BLUE_MAX_CY_PX             66   /* 最大Y坐标（避免底部硬件干扰） */

// 形状验证阈值
#define BALL_MIN_AREA_PX              10   /* 最小面积 */
#define BALL_MAX_AREA_PX            3200   /* 最大面积 */
#define BALL_COMPACTNESS_MIN          50   /* 边界框填充率最小值（%） */
#define BALL_MAX_ASPECT              160   /* 最大长宽比 */
#define BALL_AXIS_RATIO_MIN_MILLE    750   /* 主轴比最小值（千分比） */
```

### 识别逻辑（ball_vision.c）

1. **像素分类**（第630-639行）：每个像素必须满足以下所有条件才能被归类为蓝球：
   - `b - r >= BALL_BLUE_MIN_BR_DOM`
   - `b - g >= BALL_BLUE_MIN_BG_DOM`
   - `b >= BALL_BLUE_MIN_B`
   - `saturation >= BALL_BLUE_MIN_SAT`

2. **形状验证**（第357-399行）：通过色度筛选的区域必须满足：
   - 面积在 `BALL_MIN_AREA_PX` 和 `BALL_MAX_AREA_PX` 之间
   - 边界框填充率 >= `BALL_COMPACTNESS_MIN`
   - 长宽比 <= `BALL_MAX_ASPECT`
   - 主轴比 >= `BALL_AXIS_RATIO_MIN_MILLE`

3. **额外过滤**（第371-387行）：蓝球还需要满足：
   - 中心Y坐标 <= `BALL_BLUE_MAX_CY_PX`
   - 最大亮度 - 最小亮度 >= `BALL_BLUE_GRADIENT_MIN`

## 潜在问题

### 问题1：色度优势阈值过高
- 在低光照条件下，RGB三个通道的值都会成比例降低
- B-R和B-G的差值可能小于25，导致蓝球像素被过滤
- 远处小球由于像素数少，边缘模糊，色度优势更不明显

### 问题2：蓝色通道绝对下限过高
- `BALL_BLUE_MIN_B = 50` 意味着蓝色通道必须至少为50
- 对于远处小球或背光场景，整个图像亮度较低，蓝色通道可能达不到50
- 即使色度优势很明显，也可能因为绝对亮度不足而被拒绝

### 问题3：饱和度阈值问题
- `BALL_BLUE_MIN_SAT = 45` 要求饱和度至少45
- 低光照下，即使相对色度满足，绝对饱和度可能达不到
- JPEG压缩会损失色度信息，进一步降低饱和度

### 问题4：球体明暗梯度要求过高
- `BALL_BLUE_GRADIENT_MIN = 3` 要求球体内部至少有3级亮度变化
- 对于直径只有6-8像素的小球：
  - 像素数少，梯度可能不明显
  - JPEG压缩会平滑亮度变化
  - 光滑表面或特定光照角度下梯度更小
- 这会正确拒绝平面蓝色斑点，但也可能拒绝合法的小球

### 问题5：形状验证过于严格
- `BALL_COMPACTNESS_MIN = 50%` 要求边界框填充率至少50%
- 对于小球：
  - 边缘效应明显，边界框包含大量背景像素
  - 填充率可能低于50%
- `BALL_AXIS_RATIO_MIN_MILLE = 750` 要求主轴比至少0.75
- 小球由于边缘不平整或部分遮挡，主轴比可能达不到

### 问题6：Y坐标限制过严
- `BALL_BLUE_MAX_CY_PX = 66` 限制蓝球只能在Y<=66的区域
- 在120x80网格中，这意味着蓝球不能占据底部区域
- 当球体接近车头时，Y坐标可能超过66而被过滤

## 推荐解决方案

### 方案A：保守调整（推荐优先尝试）

只调整蓝球相关的阈值，保持其他参数不变：

```c
// 在 board_config.h 中修改以下参数

// 降低色度优势阈值（从25降至20）
#define BALL_BLUE_MIN_BR_DOM            20
#define BALL_BLUE_MIN_BG_DOM            20

// 降低蓝色通道绝对下限（从50降至40）
#define BALL_BLUE_MIN_B                 40

// 降低饱和度阈值（从45降至35）
#define BALL_BLUE_MIN_SAT               35

// 降低明暗梯度要求（从3降至2）
#define BALL_BLUE_GRADIENT_MIN           2

// 稍微放宽Y坐标限制（从66增至72）
#define BALL_BLUE_MAX_CY_PX             72

// 降低最小面积要求（从10降至6，允许更小的球）
#define BALL_MIN_AREA_PX                6

// 降低边界框填充率要求（从50降至40）
#define BALL_COMPACTNESS_MIN            40

// 略微降低主轴比要求（从750降至650）
#define BALL_AXIS_RATIO_MIN_MILLE       650
```

**优点**：
- 风险最小，只针对蓝球调整
- 不会影响红球识别和口袋检测
- 保持了对假阳性（阴影、反光）的基本过滤

**缺点**：
- 可能增加少量误检
- 如果问题不是阈值问题，可能需要更深入的调整

### 方案B：中等调整（如果方案A效果不明显）

在方案A的基础上，进一步放宽限制：

```c
// 更激进的阈值调整
#define BALL_BLUE_MIN_BR_DOM            15
#define BALL_BLUE_MIN_BG_DOM            15
#define BALL_BLUE_MIN_B                 30
#define BALL_BLUE_MIN_SAT               25
#define BALL_BLUE_GRADIENT_MIN           1   // 几乎不检查梯度
#define BALL_BLUE_MAX_CY_PX             75
#define BALL_MIN_AREA_PX                4
#define BALL_COMPACTNESS_MIN            35
#define BALL_MAX_ASPECT                180
#define BALL_AXIS_RATIO_MIN_MILLE       550
```

**优点**：
- 适应更广泛的场景
- 对远距离、低光照小球更友好

**缺点**：
- 误检风险增加
- 可能识别到蓝色反光或硬件部件

### 方案C：自适应阈值（需要代码修改）

添加基于场景亮度的自适应阈值：

```c
// 在 ball_vision.c 中添加

// 基于桌子亮度的动态阈值
static void compute_adaptive_thresholds(const ball_vision_result_t *result,
                                        int *br_dom, int *bg_dom,
                                        int *min_b, int *min_sat)
{
    // 根据桌子亮度调整阈值
    const unsigned table_luma = result->table_luma;

    // 暗场景：降低阈值
    if (table_luma < 120) {
        *br_dom = 15;
        *bg_dom = 15;
        *min_b = 30;
        *min_sat = 25;
    }
    // 中等场景：使用默认值
    else if (table_luma < 200) {
        *br_dom = 20;
        *bg_dom = 20;
        *min_b = 40;
        *min_sat = 35;
    }
    // 亮场景：保持当前值
    else {
        *br_dom = 25;
        *bg_dom = 25;
        *min_b = 50;
        *min_sat = 45;
    }
}
```

然后在像素分类时使用这些动态阈值。

**优点**：
- 自动适应不同光照条件
- 在低光照时更敏感，在高光照时保持严格

**缺点**：
- 需要修改代码
- 需要测试各种光照场景

### 方案D：诊断工具（先确定问题根源）

在实现任何修改之前，先添加诊断输出：

```c
// 在 ball_vision.c 的 analyze() 函数中添加

// 在 out->valid = true; 之前添加：
ESP_LOGI(TAG, "Ball vision diagnostics:");
ESP_LOGI(TAG, "  Table luma: %u", table_luma);
ESP_LOGI(TAG, "  Red pixels: %u, Blue pixels: %u, Pocket pixels: %u",
         red_px, blue_px, pocket_px);
ESP_LOGI(TAG, "  Red ball: present=%d, area=%u, radius=%d, cx=%d, cy=%d",
         out->balls[BALL_COLOR_RED].present,
         out->balls[BALL_COLOR_RED].area,
         out->balls[BALL_COLOR_RED].radius,
         out->balls[BALL_COLOR_RED].cx,
         out->balls[BALL_COLOR_RED].cy);
ESP_LOGI(TAG, "  Blue ball: present=%d, area=%u, radius=%d, cx=%d, cy=%d",
         out->balls[BALL_COLOR_BLUE].present,
         out->balls[BALL_COLOR_BLUE].area,
         out->balls[BALL_COLOR_BLUE].radius,
         out->balls[BALL_COLOR_BLUE].cx,
         out->balls[BALL_COLOR_BLUE].cy);

// 在 pick_best_ball() 中，对每个候选组件添加诊断：
ESP_LOGI(TAG, "    Blue component %u: area=%d, compactness=%u%%, aspect=%d, axis=%d, luma_range=%d",
         i, c->area, bbox_fill_percent(c),
         (w > h ? w*100/h : h*100/w),
         axis_ratio_mille(c),
         c->luma_max - c->luma_min);
```

然后在串口监视器中观察：
1. 有多少像素被分类为蓝色（`blue_px`）
2. 有多少候选组件被找到
3. 每个候选组件为什么被拒绝（形状、梯度、Y坐标等）

**优点**：
- 精确定位问题
- 避免盲目调整
- 可以基于实际数据优化

**缺点**：
- 需要先运行并观察日志

## 实施建议

### 第一步：添加诊断输出（方案D）
1. 在 `ball_vision.c` 中添加ESP_LOGI诊断信息
2. 运行程序，观察蓝球识别失败时的日志
3. 确定是哪个检查导致蓝球被过滤

### 第二步：根据诊断结果选择方案
- 如果蓝色像素很少 → 调整色度阈值和饱和度阈值（方案A或B）
- 如果蓝色像素多但没有候选组件 → 调整最小面积
- 如果有候选组件但形状检查失败 → 调整形状阈值
- 如果形状检查通过但梯度或Y坐标检查失败 → 调整 `BALL_BLUE_GRADIENT_MIN` 或 `BALL_BLUE_MAX_CY_PX`

### 第三步：渐进式调整
1. 先尝试方案A（保守调整）
2. 如果效果不够，尝试方案B（中等调整）
3. 如果光照变化很大，考虑实现方案C（自适应阈值）

### 第四步：验证
1. 在各种光照条件下测试
2. 确保红球识别不受影响
3. 确保不增加过多的误检（如识别到蓝色硬件部件）

## 调试技巧

1. **使用Wi-Fi流查看实时图像**
   - 连接到 `vison_car` WiFi
   - 访问 `http://192.168.4.1/` 查看实时图像和识别结果

2. **查看串口日志**
   - 添加诊断输出后，观察：
     - `blue_px`：有多少像素被分类为蓝色
     - `table_luma`：当前桌子亮度
     - 候选组件的详细信息

3. **手动测试**
   - 在不同光照、距离、角度下测试
   - 记录哪些情况下识别成功，哪些失败

4. **对比测试**
   - 在相同条件下测试红球和蓝球
   - 如果红球正常而蓝球失败，问题在于蓝球特有的阈值
